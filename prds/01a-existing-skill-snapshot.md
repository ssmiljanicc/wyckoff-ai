## 3. Existing output contract (SKILL.md §Output Contract)

```
1. Context
2. Wyckoff story
3. Phase and event evidence
4. Crypto-specific overlays
5. Leading scenario
6. Alternate scenario(s)
7. Trigger, invalidation, target path
8. What would change the read
9. Trade / wait / no-trade conclusion
```

**Quality:** This is a genuinely good contract. It enforces:
- Explicit context before patterns
- Plain-language story before labels
- Required uncertainty surface (alternates)
- Explicit trigger + invalidation (no hand-waving)
- Decision is allowed to be "no trade" (anti-FOMO)

**#8 disposition:** **Keep all 9 sections.** The only candidate for revision is whether sections 5/6 should be a structured tree or prose — PRD-02 should decide. Section 4 (crypto overlays) may also benefit from being a numbered checklist instead of prose, per the existing `scenario_playbook.md` §4.

**Big question for PRD-02:** does this contract apply to ALL queries, or only to scenario-building queries? Simple definitional queries ("what is a spring?") shouldn't need the 9-section structure. The skill needs a discriminator: scenario mode vs. definitional mode.

## 4. Tactical quality taxonomy (`scenario_playbook.md` §7)

This is a high-value piece of vocabulary the rebuild must preserve:

- `Phase C aggressive` — earliest entry, lowest confirmation
- `Phase D confirmation` — mid-quality
- `Phase E continuation` — latest entry, highest confirmation
- `watchlist only` — not ready
- `no-trade` — actively wrong setup

**#8 disposition:** **Wire into `scenarios/output-contract.md`** as a required field in the output. This is more useful than a confidence score because it's actionable (each tier has different position-sizing implications).

## 6. What rebuild MUST preserve (non-negotiable)

These are the load-bearing principles of the existing skill. If any are lost in the rebuild, it's a regression:

1. **Label last.** Read price/volume first, label second. This is the core anti-curve-fitting rule.
2. **Context outranks pattern.** A spring in the wrong background is noise.
3. **Scenarios, not certainties.** Output is always a tree with explicit alternates.
4. **Trigger + invalidation are mandatory.** No directional read without both.
5. **No-trade is a valid output.** Mixed evidence → wait, not forced thesis.
6. **Crypto overlays before execution.** Intermarket + BTC leadership + rotation, in that order.
7. **Action → Test → Confirmation.** Never chase the first signal.
8. **Failed signals are information, not nuisance.** Updates the thesis immediately.

All of these are already in the existing core rules + workflow. #8 should keep them verbatim or with only minor language tightening.

## 7. What rebuild CAN improve

| Problem in existing skill | Improvement opportunity in rebuild |
|---|---|
| References to raw assets/ are by file path; no provenance to specific passages | Wiki citations with frontmatter `sources:` + inline links |
| 5 distilled .md files are siloed — duplication and drift risk | Single source of truth (wiki); distilled refs either deleted or become navigation shims (per #8 architectural option B or A) |
| Output contract is one-size-fits-all (9 sections always) | Discriminator: scenario mode vs. definitional mode vs. "what is X?" |
| No examples in the output contract — agent has to guess | Wiki should contain ≥3 worked examples in `scenarios/` |
| No mechanism for the agent to *cite* what it learned from where | Wiki provenance enables footnotes/citations in agent output |
| Chart images are referenced only by URL or absent | Images are local under `raw/`, with Vision-generated captions |
| Skill-updator.md is a manual process | After rebuild, "update the skill" = "ingest new sources into wiki" — mechanical |

## 8. Open questions for PRD-02

These cannot be answered from existing skill content alone — they're product/UX decisions:

1. **Who is the user?** Solo trader watching charts? Wyckoff learner? Both? Different default modes.
2. **What's the most common query?** Scenario building? Concept lookup? Phase identification? Chart annotation? Output contract differs per mode.
3. **What's the boundary on trade signals?** The existing skill is careful to say "scenarios not certainties" but never explicitly says "no actionable buy/sell calls." PRD-02 should make this explicit.
4. **What level of effort/output is expected?** A one-paragraph quick read? A full 9-section analysis? Configurable?
5. **MCP integration:** when the agent has live data (M4), does the output contract change? Does it always pull data, or only on request?
